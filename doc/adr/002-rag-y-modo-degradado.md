# ADR-002: RAG clínico extractivo y degradación explícita

- **Estado:** Aceptado
- **Contexto:** Toda afirmación clínica debe provenir del corpus oficial y llevar una cita; si no existe evidencia, no se puede generar contenido. El proveedor de IA puede fallar.
- **Decisión:** Usar Spring AI/OpenAI para la generación y un corpus versionado local con recuperación léxica determinista, dado el tamaño pequeño y fijo del corpus de referencia. Se entrega al modelo únicamente evidencia recuperada y se solicita copiar frases literales con su ID. La API valida que cada cita pertenece a los resultados y que el texto sin citas es un fragmento literal de la evidencia; de lo contrario devuelve el extracto oficial literal. Sin coincidencias, devuelve el aviso fijo sin llamar al modelo. Circuit breaker Resilience4j y cualquier indisponibilidad del proveedor producen HTTP 503; no se inventa una respuesta degradada.
- **Consecuencias:** Las respuestas son trazables y el filtro impide aceptar texto clínico no presente literalmente en las fuentes. La búsqueda léxica puede no encontrar sinónimos y el corpus requiere aprobación/versionado clínico. La comprobación literal es deliberadamente restrictiva y no equivale a validación médica. No se envían preguntas sin evidencia al proveedor.
- **Alternativas consideradas:** vector store externo (coste operacional y embeddings innecesarios para tres protocolos); respuesta libre del LLM (no permite asegurar citas ni contenido sustentado); fallback generativo al fallar el proveedor (riesgo de contenido no respaldado).
