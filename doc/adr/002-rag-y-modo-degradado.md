# ADR-002: RAG clínico extractivo y degradación explícita

- **Estado:** Aceptado
- **Contexto:** Toda afirmación clínica debe provenir del corpus oficial y llevar una cita; si no existe evidencia, no se puede generar contenido. El proveedor de IA puede fallar.
- **Decisión:** Usar Spring AI con Google Gemini para la generación y Redis Stack/RediSearch como vector store, con embeddings `gemini-embedding-001` de 768 dimensiones y tarea `SEMANTIC_SIMILARITY`. Al iniciar, el asistente crea el esquema Redis sin depender del proveedor y luego intenta indexar los documentos del corpus versionado `clinical-protocols.json`; si embeddings no están disponibles, registra una advertencia e inicia en modo degradado. Un circuit breaker Resilience4j compartido protege las llamadas de embeddings y generación. Las consultas recuperan el protocolo más similar con umbral configurable (`RAG_SIMILARITY_THRESHOLD`, por defecto `0.82`). Redis retorna el ID del protocolo y la aplicación usa el contenido del catálogo local como evidencia; se solicita al modelo copiar frases literales con su ID. La API valida que cada cita pertenece a los resultados y que el texto sin citas es un fragmento literal de la evidencia; de lo contrario devuelve el extracto del corpus. Sin coincidencias sobre el umbral, devuelve el aviso fijo sin llamar al modelo de chat. Sin proveedor disponible o con el circuit breaker abierto, las consultas RAG producen HTTP 503 explícito; no se inventa una respuesta degradada. Triage publica eventos sin llamadas al asistente, por lo que su disponibilidad es independiente.
- **Consecuencias:** La similitud semántica puede recuperar protocolos pese a diferencias de vocabulario, pero el umbral necesita evaluación con preguntas representativas para evitar omisiones o falsos positivos. Redis debe incluir RediSearch/vector search; la imagen local es Redis Stack y en producción se requiere un servicio compatible con índices vectoriales. El corpus se re-embebe al iniciar y las preguntas se envían a Google para crear embeddings y generar respuestas, por lo que existen costos, latencia y consideraciones de privacidad. Las respuestas siguen limitadas por la verificación literal; esto no equivale a validación médica. El corpus requiere aprobación/versionado clínico.
- **Alternativas consideradas:** recuperación léxica local (menor complejidad, pero no encuentra bien sinónimos); otros vector stores (no aportan ventaja clara al despliegue actual que ya usa Redis); respuesta libre del LLM (no permite asegurar citas ni contenido sustentado); fallback generativo al fallar el proveedor (riesgo de contenido no respaldado).
